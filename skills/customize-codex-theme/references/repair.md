# Theme repair

Use this reference for disappearance after restart/update, incomplete surfaces, low contrast, overlap, white bands/halos, distorted pet windows, or broken launcher icons.

## Root-cause loop

1. Run `doctor`; capture Codex version, actual launch path, selected/next/loaded theme, launcher metadata, and renderer identity.
2. Select the exact CDP target by verified URL and renderer anchors; never use the first `app://` target. Reproduce the exact surface, state, and width. Refuse any route-changing probe while the composer has a draft or attachment; never capture private draft content merely to make restoration possible. Capture computed styles for the actual component root, every opacity-bearing ancestor, representative descendants, pseudo-elements, siblings, and their fade or gradient layers. When visible pixels disagree with computed styles, enumerate every geometrically intersecting painted element and its stacking context; `elementsFromPoint()` omits `pointer-events: none` overlays and is not sufficient by itself. Valid selectors use stable `data-*`, role/state attributes, verified ancestry, or a native ARIA relationship such as trigger `aria-controls` to popup ID. Localized visible text or localized `aria-label`, `nth-child`/position, screen coordinates, screenshot geometry, and guessed shortcuts are not stable selectors; if no stable anchor exists, stop with `UNSUPPORTED`.
3. Add the smallest failing automated guard. Fix the narrow shared root cause; never compensate with a broad global selector.
4. Exclude avatar, pet, browser, login, and auxiliary renderers before injection. Re-run the complete surface QA.
5. If the user has not authorized a themed restart, prepare only and report `PARTIAL`; do not claim the live defect is fixed.

For a migrated theme, re-run [theme-migration.md](theme-migration.md). Compare the native baseline with the migrated renderer and update the migration ledger; do not restore visual fidelity by reintroducing a dropped global control, form-shape, geometry, or localized selector.

If CDP disconnects during diagnosis, re-verify the exact owner, target ID, renderer anchors, and theme hash before restoring the captured UI snapshot. If that identity cannot be recovered, stop automation, report `PARTIAL` with the unrestored fields, and do not connect to another target merely to finish cleanup.

Rollback is required when renderer identity is wrong; permission, destructive, send, or stop controls become unreadable/inoperable; decoration intercepts input; task access regresses; an unexpected listener/config/app mutation appears; or verified cleanup cannot complete. A non-critical decorative defect may remain loaded as `PARTIAL` only when navigation, task access, controls, readability, and rollback remain safe.

## Failure map

| Symptom | Root check | Response |
| --- | --- | --- |
| Theme disappears after restart | Which launcher was used; `nextLaunchTheme` versus `loadedTheme` | Direct the user to **Codex Themes**. Official/taskbar/app-internal restart stays native. |
| Legacy **Codex Themes** opens directly without a selector | Read back target, arguments, working directory, description, path, and owner | Upgrade transactionally only when all fields match the known legacy managed signature; otherwise refuse. Preserve **Codex Original** bytes. |
| Legacy **Codex Dream Skin** fails or conflicts with Themes | Read back its exact shortcut signature, `CodexDreamSkin` state/logs, and the new catalog | Only an exact known One Piece launcher may be archived through Windows `migrate` after the new managed launchers and migrated pack validate. Preserve an archive copy; leave unknown shortcuts untouched. |
| **Codex Themes** exits before the selector with `Command returned invalid JSON` at a non-ASCII theme field | Re-run `doctor` from a CP936 console and inspect the Node JSON capture boundary | Require explicit UTF-8 stdout capture that is independent of the console code page; never repair this by removing or transliterating localized metadata. |
| A same-name shortcut only partially resembles the managed launcher | Ownership proof is incomplete or contradictory | Treat it as user-managed, report the collision, and do not edit it. |
| Cancelling the selector changes state or launches Codex | Compare the state file before/after cancel, Escape, and window close; inspect callback ordering | Fail the selector contract. Cancel must invoke neither selection nor launch and must leave state byte-for-byte unchanged. |
| Two selectors or launches appear | Confirm the start mutex is acquired before the dialog and held through launch | Refuse the second workflow; do not add a separate UI mutex or start a second watcher. |
| **Codex Themes** reports `injection failed`, but a later one-shot check passes | The loopback endpoint appeared before the exact task renderer and stable anchors were ready | Keep endpoint and exact-renderer waits separate; use the bounded cold-start renderer timeout, preserve the structured injector reason, and remove any partial injection on timeout. Do not accept an avatar, login, browser, or incomplete app shell as readiness. |
| An unvalidated or stale theme appears/selects | Compare UI items and returned ID with the freshly validated manifest catalog | Reject the ID before mutation and refresh the catalog; never resolve arbitrary pack paths from UI text. |
| Selector migration changed **Codex Original** | Compare preflight signature and file hash/bytes | Roll back the Themes migration and restore its backup; do not rewrite Original as part of migration. |
| `restore` sees a running Codex but cannot verify its theme endpoint | Compare exact Codex PIDs, recorded port/runtime identity, and loopback ownership before stopping anything | Fail closed and preserve watcher/runtime/theme state. Ask for a normal exit or recover the exact endpoint; never mark restored while live CSS may remain. |
| Launcher is blank or broken after an update | Target and `IconLocation` contain a versioned package path | Use the stable platform entry and a per-user cached icon; edit only verified theme-owned launchers. |
| Stable icon exists and matches, but Explorer still shows a blank icon | Shell cache is stale | Refresh or notify Windows Shell only; do not rewrite the shortcut or restart Codex. |
| Home is themed but another pane is blank/native | Missing surface or state coverage | Keep `PARTIAL` and run the full matrix. |
| Browser toolbar is visible but every webpage is black | The main theme repainted the native `<webview>` fallback or an obsolete iframe selector missed the current Browser host | Confirm the guest renderer itself is healthy, map the stable `data-browser-sidebar-webview` host, restore the pre-theme native background and color scheme, and add the Browser matrix cell. Never force visibility or inject the guest page. |
| Text is faint | Foreground token versus actual artwork | Derive and validate a stable contrast token with an opaque fallback. |
| All buttons gain borders, capsule radii, black fills, or identical states | Shared base or pack CSS contains a global/unscoped `button` or `[role="button"]` paint rule | Remove the broad rule, use a stable component/state anchor, and verify primary, secondary, destructive, disabled, close, and icon-only controls separately. The static audit must reject the old selector. |
| A composer repair changes dialogs, settings, or unrelated inputs | The selector infers ownership from `form:has(textarea)` or `form:has([contenteditable])` | Use the verified composer root or semantic `data-*` anchor. Form shape is not component identity. |
| Cards overlap | Geometry at the current width | Assert a positive gap and repair the shared layout rule. |
| Composer has a white band or halo | Parent/sibling fade, pseudo-element, gradient, or inset shadow | Inspect outside the composer before changing the composer itself. |
| Settings navigation is themed but the content pane is a flat native block | A repeated `data-settings-panel-slug` navigation button was mistaken for the settings paint root, a nested structural `.main-surface` covers the workbench raster, or the correct root carries an overly opaque veil | First prove semantic ownership and inspect the root's computed alpha plus large descendants. Derive the large sibling/ancestor content root from stable navigation markers when mapping is wrong; clear only its nested structural main surface. When mapping is already correct, restore the shared 52%/60%/68% settings material instead of adding a per-theme patch. Keep cards, controls, menus, dialogs, and fields opaque; never target a localized settings label or the first marker. |
| Rich `role="tooltip"` plan panel is unreadable | Capture computed styles for the root, token-colored descendants, and SVG; the role may also serve small tooltips | Use one surface compatible with both forms, or narrow by a verified stable child anchor; never judge contrast from the root alone. |
| Terminal is white only in one mount | Compare right-panel and bottom-panel variables plus xterm viewport/rows | Put terminal variables on the stable terminal root, not the mount container, then verify both mounts. |
| Utility cards look right but tabs or close buttons change | A broad `aside button` rule leaked across roles | Scope the rule to the launcher rows and verify tabs, selected state, and close controls separately. |
| A launcher menu shows padded strips around otherwise-correct rows | A broad menu/popup rule painted the native outer shell and exposed its layout padding | Link the stable tab-strip trigger to its menu through `aria-controls`; mark only that menu, make the shell transparent/padding-free, and leave row styling scoped to the rows. |
| A side-panel tab title stays faint after header fixes | The tab strip is a separate app-shell root, or an ancestor controller still applies opacity | Inspect `[data-app-shell-tabs]`, the tab-strip/controller roots, disabled state, nested token-colored spans, SVG, close, and add buttons; set readable tokens at the real root instead of adding more `header` rules. |
| A side-panel tab exists and is draggable/clickable but is visually replaced by a white top strip | Compare the tab rectangle with all geometrically intersecting paint layers, including `pointer-events: none`; inspect `header[data-app-shell-application-menu-bar="true"]` separately from its semantic header child | Keep the outer application-menu-bar drag surface transparent in shared `base.css`; paint only the semantic child and app-shell tabs. Do not change z-index, pointer events, geometry, or add a per-theme patch. Require both computed transparency and an exact-tab pixel guard before calling it fixed. |
| Suggestion circles are centered but all glyphs lean the same direction | The native icon wrapper still applies layout such as `justify-start`; SVG transforms are not the shared cause | Measure container and glyph centers, then center the direct wrapper with flex/grid alignment. Do not replace or hand-offset individual SVGs. |
| A file edit or hot apply looks fixed but reverts after reload | The live watcher cached an older payload, or the renderer CSS hash differs from disk | Apply the eligibility gate in `theme-migration.md`; compare disk, full payload, live CSS, runtime, and watcher hashes. A stale watcher blocks one-shot injection and a second watcher: validate disk, report `PARTIAL`, and wait for the next themed launch. |
| The recorded watcher is stopped but the current window still has the exact verified theme payload | Compare canonical runtime identity, theme directory, port, disk payload hash, and live renderer payload hash | Under the shared state mutex, start one replacement watcher only after every identity and hash matches; otherwise refuse. This recovery does not authorize a Codex restart or an unpaired watcher. |
| The recorded port/PID differs from the verified listener or watcher | Runtime state is stale | Report `PARTIAL`/`NOT_READY`; do not kill the unrecorded process. Reconcile through verified recorded identity or an authorized themed restart. |
| Pet/avatar window is distorted | Wrong renderer accepted | Tighten renderer identity and remove partial injection. |

Never broaden main-renderer matching to clean an auxiliary window. Cleanup-only removal is allowed only when the exact CDP target ID, signed Codex owner, recorded injector/session, and theme hash all match; it must not inject or apply styles. Otherwise stop and wait for a normal close or the next **Codex Original** launch.

After a Codex update, capture the new version and failed probe. If anchors changed, keep the native interface active until the adapter and full QA pass again.
